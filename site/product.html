Capability

Bounded-latency kill switch

C003C006

In Kubernetes deployments, the kill switch blocks new LLM requests within 1 millisecond and terminates active tunnels within 1.2 seconds. Kill state persists through restarts and power loss. Budget pre-reservation bounds cost overrun to ~$0.60 regardless of agent behavior.

The kill switch operates at three granularities: global (all agents), team (all agents in a team), and individual agent. Graduated enforcement escalates automatically through five levels: warning, throttle, quarantine, block, and kill.

In Kubernetes: network-level enforcement, agents cannot bypass. In Docker/advisory mode: best-effort enforcement via proxy routing.

Capability

Authority that can only attenuate, never escalate

E005B004B006

When an orchestrator delegates to a worker agent, Altrace enforces that the worker's authority is a strict subset of what it was granted. Budget limits, model access, tool permissions, data classification, time windows, rate limits, and geographic constraints — all governed by cryptographically signed delegation contracts.

This isn't policy-enforced. It's mathematically enforced. Authority attenuation makes escalation structurally impossible, not just prohibited.

Content-blind: Altrace never reads the content of prompts or responses. Only boolean governance labels flow through the system — your data stays with your agents.

Capability

Every decision. Immutable. Attributable.

E004E008D003

Altrace records every enforcement decision in a tamper-evident audit log. Request ID, agent identity, the specific stage in the 31-stage decision chain that produced the result, delegation contract reference, and machine-readable reason code — all signed and stored.

When an auditor asks what happened, you don't search through prompt logs. You have causal records: which agent, what it tried to do, which governance rule was evaluated, and the outcome — with full attribution chain.

EU AI Act Art. 50 requires transparency in AI-generated content. Altrace produces machine-readable decision reasons and transparency headers for every governance action.

Capability

MCP tool governance at the protocol layer

C009B007

Altrace governs Model Context Protocol traffic with a six-layer defense: server registry authorization, tool-level fingerprint verification, supply chain attestation, tool description poisoning detection (89 RE2 patterns), per-tool cost caps, and team-scoped access control.

When a new MCP server appears in your infrastructure, Altrace detects it. When a tool description changes between calls — a rug pull attack — fingerprint verification blocks it. When tool descriptions contain hidden prompt injection, poisoning detection catches it before execution.

OWASP MCP Top 10 coverage: tool poisoning (MCP03), privilege escalation (MCP02), audit trail (MCP08), and shadow MCP detection (MCP09). All enforcement decisions recorded with causal audit records.

Capability

Agents must prove before they act

D005C004

Evidence grounding requires agents to demonstrate they've gathered prerequisite information before executing destructive operations. An agent can't issue a refund without first looking up the order. Can't delete a record without first verifying it exists.

Evidence rules are defined in the safety manifest. When an agent attempts a destructive tool call, Altrace checks the session's evidence trail — with time bounds. Stale evidence is rejected. Missing evidence is blocked. The agent receives a provider-native error response explaining exactly what evidence is missing, enabling self-correction.

Self-repair feedback: block responses are formatted in each LLM provider's native error format (Anthropic, OpenAI, Gemini). Agents can parse the response and automatically retry with the correct prerequisite calls.
altrace — evidence-grounding.log
14:24:01 BLOCK support-bot
  tool=issue_refund action=destructive
  missing=lookup_order (required, max_age: 5m)
  self_repair=true
14:24:05 ALLOW support-bot
  tool=lookup_order evidence=recorded
14:24:08 ALLOW support-bot
  tool=issue_refund evidence=valid (3s ago)

Capability

Real-time stream scanning with mid-flight cancellation

A002C005

Altrace scans SSE streaming responses in real time as tokens arrive. Each event is classified against content governance policies. When a violation is detected — PII in the response, forbidden content, policy breach — the stream is cancelled immediately with a protocol-compliant SSE error event.

A sliding window reassembles content across event boundaries to detect PII that arrives split across multiple tokens. Provider-agnostic: same scanning pipeline for Anthropic, OpenAI, and Gemini streaming responses.

Content-blind classification: RE2 regex patterns produce boolean labels only. Matched content is never extracted, stored, or transmitted. Your data stays in transit.
altrace — stream-scan.log
14:25:00 SCAN analyst-2
  stream=active events=47 status=clean
14:25:12 CANCEL writer-1
  stream=cancelled at_event=23
  label=pii-ssn window=cross-event
  action=sse_error_injected + connection_closed

SDKs

Optional SDKs for deeper integration

Altrace works without any SDK changes — it's a transparent proxy. But optional SDKs add evidence headers, budget awareness, and framework integration.

from altrace import AltraceClient

# Drop-in replacement for anthropic.Anthropic()
client = AltraceClient(
    provider="anthropic",
    team="research",
    agent="data-analyst-1",
)

# Evidence headers attached automatically
response = client.messages.create(
    model="claude-sonnet-4-5-20250929",
    messages=[{"role": "user", "content": "Analyze Q3 data"}],
)

# Budget-aware: client.budget_remaining returns float
print(f"Remaining: ${client.budget_remaining:.2f}")
